## Build R — reference, examples, screenshots (needs Rhino)

1. A rhino-smoke spec that dumps every BEMGen component's metadata (panel, name, nickname, GUID, description, exposure, inputs and outputs with their types, access, optional flag, defaults, descriptions) to JSON outside the repository; `component_reference.py` renders the component pages from it and copies the icons. Re-running both is how the reference is updated (used by `sync-docs`).
2. The example definitions: for each typology a definition presets → generator → simplifier → aggregator → *Convert2BEM* (and *Convert2IDF* with Write off), laid out readably with groups and short scribbles, saved as `.gh`; `end-to-end.gh` for the walkthrough of `example-end-to-end.md`. Each is reopened headless and must solve without errors.
3. Screenshots, captured by script: the viewport previews of each typology's plan and building, and the canvas of each example. If the canvas cannot be captured headless, report it; the controller then asks the owner for screen control.

## Build W — site, skill, package, license

1. MkDocs site (Material theme, pinned requirements), the user part (the pages above, written for a new user; the workflow guide covers presets → generator → simplifier → aggregator → validation → *Convert2BEM* / *Convert2IDF*, Preview Location, Transform Plan, storeys, the any-program preset, the heat-transfer options), the end-to-end example (the linear plan through *Perimeter Core* and *Stack* to *Convert2BEM* and *Convert2IDF*, with every input value and the expected outputs), the developer part assembled at build time, and clear separation of the two (navigation, landing pages, styling).
2. `sync-docs` skill: compares the generated component reference with the current plugin (via the metadata spec, or by reading the component sources when Rhino is not available), checks user pages against component names, inputs, and defaults, checks the developer docs against the decision log and ADR statuses, and writes a plan of the edits needed; it never edits on its own unless asked.
3. Yak package script and manifest, `LICENSE`, version 1.0.0 in `Directory.Build.props` at close-out.

## Acceptance criteria

- `mkdocs build --strict` passes; `serve.ps1` serves the site on localhost; every component appears in the reference with its icon; the workflow guide and the end-to-end example match the examples and the code.
- Every example opens and solves headless without errors; the rhino-smoke specs pass.
- The Yak package builds locally with version 1.0.0; nothing is published.
- `sync-docs` run on the final tree reports the docs up to date.
- `scripts/verify.ps1` passes; a fresh clone of `v1.0.0` passes it.
